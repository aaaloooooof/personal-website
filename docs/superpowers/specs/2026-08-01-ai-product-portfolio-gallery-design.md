# 通用 AI 产品经理求职网站：夜间美术馆设计

日期：2026-08-01

## 1. 背景与目标

本项目是在现有个人主页基础上继续构建的静态求职网站。目标岗位为通用 AI 产品经理。由于缺少正式实习经历，网站不采用传统的“教育背景—实习—奖项”结构，而以真实项目案例、产品判断、AI 工作流设计和原型构建能力作为主要证据。

网站需要同时满足两个目标：

1. 形成具有记忆点的艺术化个人表达。
2. 让招聘方能够快速找到项目、简历和联系方式，并在需要时深入阅读案例。

## 2. 设计原则

- 不虚构实习、业务指标、用户规模或商业成果。
- 能力必须由项目中的实际过程和产出证明。
- 艺术体验不能遮挡求职信息。
- 桌面端强调空间感，移动端强调可读性。
- 保留现有流动封面，不重新设计首屏动画。
- 优先复用现有 Pug、Less、JavaScript 和 Gulp 构建链，不引入前端框架。

## 3. 内容信息架构

网站内容由七类模块组成：

1. **个人定位**：姓名、通用 AI 产品经理定位、一句话价值主张、求职状态。
2. **核心能力**：用户研究与需求分析、产品方案与 PRD、AI Workflow / LLM 应用设计、原型构建与快速验证。
3. **精选项目**：以 Mavis Demo Generator、LearnLoop、MirrorCampus 为首批核心案例。
4. **项目详情**：每个案例使用统一证据结构，包含问题、用户、角色、洞察、决策、原型、产出和复盘。
5. **产品思考与 AI 实践**：从现有周报中精选 3–6 篇高质量内容，不展示流水账。
6. **关于与实践档案**：教育背景、研究经历、独立实践、使用工具和工作方法。
7. **简历与联系方式**：PDF 简历、邮箱、GitHub、其他专业主页和求职状态。

“实习经历”不作为独立主模块。相关经历统一放入“实践档案”，重点展示持续构建和问题解决能力。

## 4. 视觉方向

### 4.1 流动封面

现有 WebGL 流体封面、标题、副标题和 `ENTER` 入口保持不变。若后续只修改文案，也不得改变现有动画机制和视觉气质。

### 4.2 内部空间

点击 `ENTER` 后进入“夜间美术馆”风格的横向无尽长廊：

- 深色展墙、聚光灯、作品画框、编号和展签构成主要视觉语言。
- 内容以不同尺寸的“展品”呈现，但排布必须保留清晰的视觉层级。
- 允许访客自由左右探索，不强制固定参观顺序。
- 顶部固定显示 `INDEX / ROOM MAP`、下载简历和联系方式。
- 长廊内包含定位展签、能力墙、项目画作、产品思考、个人档案和出口服务台。

### 4.3 项目观展室

点击项目画作后打开独立观展室：

- 长廊作为背景退后或淡化，案例内容成为主要焦点。
- 观展室使用纵向阅读结构，适合完整案例叙事。
- 关闭、按 `ESC` 或使用浏览器返回键后，恢复到长廊原来的浏览位置。
- 案例阅读顺序为：背景与用户问题、目标用户、个人角色、调研与洞察、关键产品决策、原型与产出、复盘与下一步。

## 5. 响应式与无障碍体验

- 桌面端支持鼠标滚轮映射横向移动、触控板横向移动、拖拽和键盘方向键。
- 移动端转换为纵向展廊，不强制横向拖动。
- 所有画作和展厅入口都可以用键盘聚焦和打开。
- 观展室打开后焦点移入内容；关闭后焦点回到原画作。
- `ESC` 关闭观展室，浏览器返回键保持一致行为。
- `prefers-reduced-motion` 开启时减少转场、视差和连续动画。
- 重要内容不依赖鼠标悬停才能发现。

## 6. 技术架构

项目继续使用静态技术栈：Pug、Less、原生 JavaScript 和 Gulp。当前流动封面相关实现保留。

建议新增或调整以下单元：

- `src/data/portfolio.json`：个人介绍、能力、项目、文章、联系方式的唯一数据源。
- `src/components/gallery-shell.pug`：长廊和固定导航容器。
- `src/components/artwork-card.pug`：长廊中的通用作品画框。
- `src/components/case-room.pug`：项目独立观展室模板。
- `src/css/gallery/gallery.less`：展厅布局、画框、灯光、观展室和响应式样式。
- `src/js/gallery.js`：横向浏览、拖拽、键盘导航、打开和关闭观展室、位置恢复与历史记录。

Gulp 构建任务需要读取 `config.json` 和 `portfolio.json`，将核心内容直接渲染进静态 HTML。JavaScript 用于增强交互，而不是生成唯一可读内容。

## 7. 状态与数据流

1. 页面首先显示现有流动封面。
2. 点击 `ENTER` 后切换到长廊，并记录当前展厅状态。
3. 长廊的所有展品从 `portfolio.json` 构建生成。
4. 打开项目时记录画作标识和长廊滚动位置。
5. 观展室通过对应项目标识显示静态生成的案例内容。
6. 关闭项目时恢复长廊位置与键盘焦点。
7. URL 哈希用于标识当前区域或项目，使直接链接和浏览器返回可用。

## 8. 降级与错误处理

- WebGL 不可用时显示静态封面背景，`ENTER` 仍然工作。
- JavaScript 不可用时，页面以纵向静态结构展示全部核心模块和项目详情。
- 图片加载失败时显示艺术化渐变占位，并保留项目名称和替代文字。
- 数据字段缺失时不显示空白标签；构建阶段应报告必填字段错误。
- 外部链接使用明确文字，不依赖图标解释含义。
- PDF 简历不存在时不显示下载按钮，避免死链。
- 加载或动画失败不能阻断项目、简历和联系方式的访问。

## 9. 测试与验收

### 构建

- `npm run build` 成功完成。
- 构建产物包含首页、样式、脚本、图片和简历资源。
- 构建过程中没有缺失必填项目数据或资源错误。

### 功能

- `ENTER` 可以从流动封面进入长廊。
- 鼠标、触控板、拖拽、触屏和键盘均可浏览。
- 项目观展室可以打开、关闭，并恢复原长廊位置。
- 浏览器前进、后退和直接项目链接行为正确。
- 简历下载、邮箱和 GitHub 链接有效。

### 视觉与响应式

- 桌面端重点验证 1440px 和 1280px 宽度。
- 移动端重点验证约 390px 宽度，并采用纵向展廊。
- 文字、展签和主要操作在深色背景上满足可读性要求。
- 动画不会造成明显掉帧；低性能设备可以减少效果。

### 无障碍与可靠性

- 键盘焦点顺序清晰可见。
- `ESC`、关闭按钮和焦点恢复正确。
- 减少动态效果设置生效。
- JavaScript 关闭后仍能阅读核心内容。
- 页面无阻断性控制台错误。

## 10. 首期范围

首期只实现求职所需的最小完整体验：保留流动封面、完成横向长廊、三个核心项目入口、独立观展室、产品思考入口、个人档案、简历和联系方式。

首期不包含后台管理系统、用户登录、评论、复杂 3D 场景、自由漫游游戏控制、内容管理平台或访问数据看板。新增内容通过编辑数据文件和静态资源完成。

## 11. 成功标准

- 招聘方在 30 秒内能识别目标岗位、核心能力和三个代表项目。
- 招聘方无需完成整条参观路线即可找到简历和联系方式。
- 每个项目都能明确说明问题、角色、决策、产出和复盘。
- 网站呈现艺术化个人风格，同时不牺牲信息可读性和移动端可用性。
- 所有公开内容真实可验证，不依赖虚构实习或指标填补经历空白。
